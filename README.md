# Organization Name — Website

A single-page internal site for a security department — hero, who-we-are,
departments, scope, stats, services, history timeline, resources
documents, resource contacts, and a monthly poll, all on one scrolling
page. Static HTML/CSS/JS, no build step and no server required: open
`index.html` in a browser and it works.

(An earlier version of this site had a separate Resources page. It was
merged into `index.html` as a single unified page — see "Page search"
below for how searching across the whole page works now.)

## Project structure

```
index.html          The entire site — every section below
README.md           This file
styles.css           All styles (see the file header inside it for a
                       section-by-section map)
script.js               All behavior (see the file header — each major
                       feature is commented where it's set up)
Fonts/
  ghawar-*.woff        Body font, 4 weights (see "Fonts" below)
  manifa-*.woff        Heading font, 4 weights
Images/
  placeholder-*.svg    20 placeholder images (hero, logo, department
                       photos, service icons, timeline photos, contact
                       photos) — see "Replacing images" below to swap
                       them for your own
```

**Keep this structure intact** when copying, zipping, or moving the
site — `index.html`, `styles.css`, and `script.js` must all sit
together, with the `Fonts/` and `Images/` folders right alongside them.
If any of these gets separated (e.g. only the HTML file gets copied out
on its own), the styling, behavior, fonts, or images will silently stop
working.

When you have real photos to add, save them into the `Images/` folder
— see "Content editing guide" below for exactly which filenames each
spot expects.

Nothing here needs a build tool, bundler, or package manager. To preview
changes, just open `index.html` directly, or serve the folder with any
static file server (e.g. `npx serve .`) if you want a clean URL.

## Major components

### Header & navigation
- **Top nav** (`.topbar`) hides when scrolling down and reappears on any
  upward scroll, to keep more of the page visible while reading. Every
  nav link is an in-page anchor (`#departments`, `#resources-docs`,
  etc.) that scrolls to that section.
- **Mobile menu** (`.menu-toggle` + `nav.links`): below 900px, the nav
  links collapse into a hamburger-triggered dropdown. The JS applies
  inline styles to reposition the same `<nav>` element rather than
  duplicating markup.
- **Scroll-spy**: an `IntersectionObserver` in `script.js` highlights
  whichever top-nav link corresponds to the section currently in view.

### Hero
Full-viewport-height section with an animated gradient background (styled
to read as a "video," with a working Pause/Play toggle). Scrolling down
even slightly snaps the page straight to the next section instead of
scrolling gradually through the hero. The trigger has a short "settle"
delay (~80ms) before it fires, so a fast scroll passing *through* that
zone on its way further down the page doesn't get incorrectly
intercepted — only a scroll that actually comes to rest there triggers
the snap.

### "Who we are" tabs
A horizontal-scrolling strip of tabs (Vision, Mission, and the values
that follow) above a single content panel that swaps text when you pick
a different tab. One function (`selectWhoTab()`) handles every way of
changing tabs — clicking one directly, using the prev/next arrows, or
auto-advance — so the active tab, the panel content, and the scroll
position can never drift out of sync. The arrows dim themselves out at
either end, the same as the Timeline and Announcements arrows.

It also auto-advances on its own timer, pausing while you hover/touch
it and pausing for longer after you deliberately pick a tab (so you get
time to actually read it) — the same behavior as the History Timeline,
including only running while the section is actually visible on screen.
The two timing numbers (`WHO_TABS_AUTO_ADVANCE_INTERVAL` and
`WHO_TABS_MANUAL_SELECT_PAUSE`) are right next to the "Who we are" tabs
setup in `script.js` if you want to adjust the speed. See "Editing the
'Who we are' tabs" below for how to add, remove, or edit an entry.

### Announcements bar
Fixed to the bottom of the viewport. Click to expand a panel with a
horizontal carousel of announcement cards. Clicking a card opens an
enlarged modal (image + details) with its own prev/next navigation.
The panel closes via its **✕ button**, a click anywhere outside it, or
**Escape** — all three call the same `closeAnnouncePanel()` function so
they can never fall out of sync. "Dismiss all" empties the bar entirely
(distinct from closing the panel, which just hides it). The pill
indicators above the cards are entirely generated by JavaScript —
always exactly one per card — so they never need manual updating.

### History timeline
Two designs were built during development; the client chose **Design 2**
(the Aramco-style timeline with a big image + caption above a horizontal
year strip). **Design 1** (a simpler dot-and-line timeline) is kept in
`index.html` as an HTML comment for reference — search for
`DESIGN OPTION 1` if you ever need to revisit it.

Design 2's key behavior: selecting a year — by clicking it, using the
prev/next arrows, or via auto-advance — always goes through one function,
`selectHv2Year()`. That's deliberate: it guarantees the active dot, the
progress rail, the image, and the caption can never drift out of sync,
because there's only one code path that changes any of them. Auto-advance
only runs while the timeline is actually scrolled into view (checked with
an `IntersectionObserver`), so it can never pull the page back to the
timeline if you've scrolled elsewhere. Same pause-on-hover /
longer-pause-after-manual-pick behavior as the Who We Are tabs, tuned by
`TIMELINE_AUTO_ADVANCE_INTERVAL` and `TIMELINE_MANUAL_SELECT_PAUSE`.

### Contact us
A two-panel card between the Resources documents and the Resource
Contacts sections: contact info (QR code, phone, email) on the left,
a "Write to us" form on the right, with Type (Suggestions/Violations/
Complaints/Volunteer) and Location dropdowns. This is a static site
with no backend, so submitting the form doesn't actually send
anywhere — it validates the fields and shows a confirmation message in
place of the button. To connect it to a real endpoint, replace the
body of the submit handler for `#contactUsForm` in `script.js` (search
for "Contact us:" there) with your own `fetch()` call or form action.
The QR code is a placeholder image — see "Replacing images" below.

### Resources (documents & contacts)
The document grid, its own local search box (`#resSearch`), category
filter pills (General instructions/SOPs/Manuals/Links), and the contact
personnel cards — originally a separate page, now the last section
(`#resources-docs`) on `index.html`, right before the footer. The local
search box and the filter pills combine (a document must match both the
active category and the search text to show); it's deliberately scoped
to just this section's documents. For searching the *whole* page
instead, see the header search box, described next.

### Page search
The header search box indexes **real text from the page itself**, not a
hand-maintained list. Typing shows a live dropdown of matches as you
type, each showing which section it's from and a snippet of surrounding
text with the match highlighted; picking one scrolls straight to it and
gives it a brief highlight flash so it's unmistakable.

How it works: every major section in `index.html` has a
`data-search-section="..."` attribute (e.g. `data-search-section=
"Departments"`). At search time, `buildSearchIndex()` in `script.js`
walks each tagged section collecting headings, paragraphs, list items,
and other content text (see `SEARCH_CONTENT_SELECTOR` there for exactly
which elements). **Two sections are handled a little differently**: Who
We Are and History are JS-driven, meaning only the currently-selected
tab/date's text actually sits in the DOM — searching would otherwise
only ever find whichever one happens to be showing. Both push their
*entire* content (all 8 tabs, all 24 dates) into the index separately as
they set themselves up (see `dynamicSearchEntries` near the top of
`script.js`), and each entry knows how to reveal itself — clicking a
Who We Are result switches to that tab first, clicking a History result
jumps to that date first, then the highlight lands on the now-visible
content.

The matching itself is case-insensitive and collapses extra/repeated
whitespace on both the query and the content, so "access   control",
"Access Control", and "ACCESS CONTROL" all find the same things. Results
where the match starts a whole word (searching "vision" finding
"**Vision**") are ranked above coincidental mid-word matches (that same
search matching inside "Safety Di**vision**") — both are shown, but the
more relevant one leads.

**To make a new section searchable**: just add `data-search-section=
"Your Label"` to its wrapping element — no JS changes needed, as long as
its content is plain DOM text and not dynamically swapped like Who We
Are/History are. **To exclude a specific element** from search results
(e.g. it's noisy or purely decorative), add `class="search-skip"` to it.

### Responsive behavior
Each component's mobile/tablet overrides live in a `@media` block near
that component's own CSS (rather than one giant breakpoint section at
the end) — this makes it much easier to find and adjust a component's
responsive behavior without hunting through unrelated rules. The main
breakpoints used are 900px (nav switches to hamburger, multi-column
grids drop a column) and 640px (single-column layouts, smaller type).

### Fonts
Two custom typefaces are self-hosted (not loaded from Google Fonts):
- **Ghawar** — body text, everywhere.
- **Manifa** — all headings (`h1`–`h3`) and title-style elements.

Both are declared via `@font-face` at the top of `styles.css`, in
four weights each (300/400/600/700), pointing to the `.woff` files in
the `Fonts/` folder (`ghawar-*.woff`, `manifa-*.woff`). They were
converted from the original `.otf` files using
[fontTools](https://github.com/fonttools/fonttools) (`pip install
fonttools`):

```python
from fontTools.ttLib import TTFont
f = TTFont('SomeFont-Regular.otf')
f.flavor = 'woff'
f.save('somefont-regular.woff')
```

IBM Plex Mono is still loaded from Google Fonts and used only for small
UI "eyebrow" labels (e.g. "OUR HISTORY") — a deliberate exception, since
those are treated as UI chrome/kickers rather than body text or headings.

## Content editing guide

This section is written for making the common day-to-day changes
**without needing to understand the rest of the codebase.** Every task
below only touches the specific spots described. Anything you add this
way is automatically picked up by the page search too, as long as it
sits inside a section with a `data-search-section` attribute (all of
the ones below already do).

### Replacing images

Every image on the site is a real `<img>` tag — not a CSS background —
specifically so you can swap one in without touching any CSS. Right now
each one points to a placeholder file (a plain colored graphic, named
`placeholder-*.svg`) so the page looks complete rather than showing
broken-image icons before you've added real photos.

**The easiest way to replace any image: keep the same filename.**
Just save your new photo over the matching `placeholder-*.svg` file
inside the `Images/` folder (or give your file that exact name) and
it'll show up immediately — no code edits needed at all.

If you'd rather use a different filename, that's fine too — just find
that image's `<img src="...">` tag in the HTML and change the filename
inside the quotes. Every image has a short comment directly above it
(or above its `<img>` tag) telling you which one it is:

| Section | Comment to find |
|---|---|
| Hero background | "HERO IMAGE — replace this" |
| Logo | just above the `<img class="brand-logo">` |
| Department photos (×6) | "DEPARTMENT IMAGES — replace here", then "Department N image goes here" per card |
| Service icons (×4) | "SERVICE ICONS — replace here", then "Service N icon goes here" per card |
| History Timeline images (×4) | comment above `.hv2-media-img` in the `<img>` tag; see also "HISTORY TIMELINE DATA" in `script.js` |
| Contact photos (×4) | "CONTACT PHOTOS — replace here", then "Contact N photo goes here" per card |
| Contact us QR code | "QR CODE — replace here" |

A few things worth knowing:

- **Photo format**: any web image format works (`.jpg`, `.png`, `.svg`,
  `.webp`) — just make sure the `src` in the HTML matches whatever
  file/extension you actually use.
- **Sizing**: every image is styled with `object-fit:cover`, meaning it
  automatically fills its frame and crops to fit without stretching —
  you don't need to pre-crop your photos to an exact size, though a
  roughly similar aspect ratio to the placeholder will crop the least.
- **The 4 History Timeline images are shared across all 24 dates** (in
  rotation — see "Editing timeline dates" below) rather than each date
  having its own unique photo. If you want every date to have its own
  image instead, add more image files and reference their filenames in
  the `hv2Slides` array in `script.js`.
- **Design 1** (the alternate History timeline, currently kept as a
  commented-out block in `index.html` since Design 2 was chosen) still
  uses the old CSS-background-gradient placeholders rather than `<img>`
  tags. It's inactive and not rendered, so this was left as-is.

### Editing the "Who we are" tabs

All 8 tabs (Vision, Mission, People Focus, Pursuit of Excellence,
Innovation and Technology, Customer Experience, Security Posture and
Branding, Quest for Safety) live in **two places that must stay in
sync**: the `<button class="who-tab">` elements in `index.html`, and
the `WHO_TABS` array in `script.js` (search for "WHO WE ARE TABS DATA"
for the full walkthrough). Quick summary:

- **Edit a tab's text**: just change its `title`/`paragraph`/`bullets`
  in the `WHO_TABS` array. No HTML changes needed.
- **Add a tab**: add a new `<button class="who-tab" data-index="N">`
  at the end of `who-tabs-track` in `index.html` (next unused number),
  then add a matching entry to the *end* of `WHO_TABS`.
- **Remove a tab**: delete its `<button>` and its `WHO_TABS` entry,
  then renumber every `data-index` after it (and the array) so the
  positions still line up with no gaps.
- Each entry is either `{ title, paragraph }` for a single block of
  text (used by Vision/Mission) or `{ title, bullets: [...] }` for a
  bullet list (used by the rest) — use whichever shape fits your
  content.

### Adding, removing, or editing a History timeline date

All of the timeline's dates live in **two places that must stay in
sync**: the `<button class="hv2-year-btn">` elements in `index.html`,
and the `hv2Slides` array in `script.js` (search for "HISTORY
TIMELINE DATA" — there's a full walkthrough in the comment right above
it). Quick summary:

- **Edit a date's description**: just change its `caption` text in the
  `hv2Slides` array. No HTML changes needed.
- **Add a date**: add a new `<button>` in `index.html` with the next
  `data-slide` number, then add a matching entry to the *end* of
  `hv2Slides` (array position must match the `data-slide` number).
- **Remove a date**: delete its `<button>` and its `hv2Slides` entry,
  then renumber everything after it so there are no gaps.

Two entries currently read "Milestone details to be added" (in the
1950s and 1960s groups) — search `script.js` for that exact phrase
to find and replace them once the real content is ready.

### Adding or removing a Resources document

Just edit the `<a class="doc-card">` cards inside `#docGrid` in
`index.html` — copy an existing one, give it the next id (e.g.
`doc-8`), and fill in its title/publisher/file type. There's no
separate list to keep in sync anymore: the page search reads document
titles directly from these cards, so a new one is searchable
automatically. Give it a `data-filter` value matching one of the
existing filter pills (`general`, `sop`, `manuals`, `links`) so it
shows up correctly when that category is selected.

## Testing checklist

There's no automated test suite (this is a static marketing/intranet
site), but before shipping a change, it's worth manually checking:
- No horizontal scrollbar appears at common widths (320–1920px)
- The announcements panel opens/closes correctly via all three methods
- The History timeline still keeps its dot/image/caption in sync after
  any edit to `selectHv2Year()` or the auto-advance logic
- The page search still finds new content after adding it (type a word
  from it into either search box)
- Fonts still load (check the Network tab for 404s on `.woff` files if
  you rename any of the `.woff` files)
